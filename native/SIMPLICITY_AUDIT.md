## Ranked actionable findings

### 1. High — current acceptance tooling has drifted from the core [demonstrated defect]

**Evidence.** [acceptance.py:43](tools/acceptance.py#L43) pins `0.5.0-geometry.2`; [coaster.hpp:16](core/include/coaster/coaster.hpp#L16) declares `0.8.3-flow.1`. [acceptance.py:308](tools/acceptance.py#L308) therefore rejects current reports before evaluating their result. Updating that string alone does not fix the tool: [acceptance.py:237](tools/acceptance.py#L237) builds the old convergence metric set and [line 268](tools/acceptance.py#L268) requires an exact count, while [convergence.cpp:91](core/src/convergence.cpp#L91) now adds force-envelope axes and utilization cases. [test_acceptance.py:21](tools/test_acceptance.py#L21), [line 50](tools/test_acceptance.py#L50) and [line 67](tools/test_acceptance.py#L67) reproduce the older protocol, including synthetic 100/200 Hz certificates. The harness validates `case.step` rather than requiring 960/1920 Hz at [acceptance.py:230](tools/acceptance.py#L230).

**Remove/own.** Bind one declared acceptance protocol to the actual selected executable/version and carry that exact binding into manifests/resume. Keep an explicit complete expected metric set; do not solve drift by accepting arbitrary extra/missing rows or relaxing rate checks. Make the C++ convergence assessment the owner of the required metric policy. The maintained audit adapter at [tools/convergence/audit.cpp:11](tools/convergence/audit.cpp#L11) repeats the old metric selection using templates that conditionally support obsolete core fields; current exact-version builds do not need those compatibility branches. Its `loadDesign` already performs mandatory replay, then [line 41](tools/convergence/audit.cpp#L41) performs another fine simulation. Retain that extra replay only if an explicitly independent-repeatability experiment requires it; otherwise report the existing complete assessment without a second, narrower comparator.

**Validate.** Run a current CLI rejection and a current accepted save/replay through the actual harness. Check wrong executable/version, absent or altered envelope rows, forged summary arithmetic, wrong rates and stale resume artifacts. Keep synthetic malformed-input tests, but add a current CLI contract test so the test factory cannot define its own obsolete truth. No historical matrix is relabeled.

**Audit reproduction.** The actual preserved [flat42 report](artifacts/flow-intent-v083-20260910/integration-20260911/acceptance-final/flat42/report.json), containing 160 convergence rows, returns `GENERATOR_MISMATCH`. Aligning only the expected version in process memory returns `CONVERGENCE_METRICS`; no source or evidence file was changed. A separate synthetic probe showed that the unchanged 100/200 Hz protocol fixture returns `accepted-candidate`. The synthetic object is a protocol reproduction, not a fabricated ride or physical acceptance result. The existing acceptance + convergence protocol suites still passed **58 tests**, demonstrating the coverage gap.

### 2. High — one itinerary has several conflicting owners [proven maintainability/design issue]

**Evidence.** [generation.cpp:163](core/src/generation.cpp#L163) maps footprints with `{1,2,1,3}`; [line 178](core/src/generation.cpp#L178) independently interprets sides. [Lines 532–571](core/src/generation.cpp#L532) build separate minimum lengths, source exits and footprints; [line 670](core/src/generation.cpp#L670) emits another side-specific ordering; [line 807](core/src/generation.cpp#L807) and [line 860](core/src/generation.cpp#L860) rediscover source and operation roles by string scans. [line 139](core/src/generation.cpp#L139) hardcodes turn signs and a four-variable closure representation. [line 629](core/src/generation.cpp#L629) even records `H-I-A` separately from `port-routed/H-I-IM-A4`. These are multiple executable descriptions of the same ride, not merely a long function.

**Remove/own.** One internal ordered list of concrete source occurrences should own identity, actual inlet/outlet pose and energy requirements, sampled footprint and attached work domains. Ranking and emission consume it. Remove the replaced side switches, mapping arrays, identity scans and redundant topology descriptions together; do not wrap them in a new general grammar. Enforce only the agreed Falcon signature relative sequence: ascent → summit → dive → fastest launch → giant camelback. Preserve loop and Immelmann presence while letting physically feasible placement determine their order. Flat terrain uses the same track progression on supports, per the main design decision.

**Validate.** Test ordered occurrence traversal, rigid transforms, actual exit heading, distinct operation/source domains and required element presence. Then verify closure, source energy, clearance and 960/1920 replay across a predeclared varied matrix. Named regression cases remain useful, but changing turn intent/rim placement until those cases pass is not proof of general routing.

### 3. High — FVD source placement preserves derivatives for only some families [proven inconsistent ownership; impact not quantified]

**Evidence.** Immelmann becomes sampled `AuthoredPoint` geometry at [generation.cpp:445](core/src/generation.cpp#L445); loop placement emits `loopShape.points` at [line 689](core/src/generation.cpp#L689). The explicit restoration of known tangent/curvature/up at [line 984](core/src/generation.cpp#L984) is called only for the tall signature and airtime at [line 992](core/src/generation.cpp#L992). **Remove/own.** Give all rigid FVD occurrences one placement path that retains their canonical derivative data and only applies the allowed rigid transform/vertical datum. Route polylines are footprint/connector inputs, not alternative owners of the source's physical jets. This removes per-family restoration and exemption rules where the source-boundary contract supersedes them. Preserve public source APIs and their diagnostics.

**Validate.** For tall hill, full loop, Immelmann/pullout and both airtime chains, compare placed position/tangent/curvature/up and boundary derivatives against the source under translation/yaw and terrain datum changes. Compare source inlet/apex/exit energy and actual full-train loads. This audit has not measured a resulting load error or claimed an existing accepted ride is numerically invalid.

### 4. Medium — immutable geometry is repeatedly rebuilt/certified within one validation transaction [proven repeated work]

**Evidence.** [clearance.cpp:71](core/src/clearance.cpp#L71) rebuilds a copied track and compares every canonical cache before constructing the sweep. [station.cpp:31](core/src/station.cpp#L31) independently performs another rebuild/cache comparison, then [station.cpp:199](core/src/station.cpp#L199) builds the sweep again. Support placement uses [supports.cpp:172](core/src/supports.cpp#L172); geometry validation uses [track.cpp:263](core/src/track.cpp#L263). Generation and persistence each orchestrate these same checks ([generation.cpp:1341](core/src/generation.cpp#L1341), [persistence.cpp:105](core/src/persistence.cpp#L105)). A completed geometry can therefore pay repeatedly for the same canonical-u certificate.

**Remove/own.** Keep public checked entry points, but let the internal final-validation transaction build one checked canonical snapshot/sweep after the final geometry/bank change and pass it to structure/geometry consumers. Keep station-specific topology, frame-domain and foundation checks. Do not add a mutable global cache, dirty flags or a persistent cache-version scheme; a local immutable result is sufficient. A later track mutation invalidates the transaction and requires a new result.

**Validate.** Existing stale-span/frame, singular-frame, cancellation, station, support, terrain and crossing counterexamples must still reject. Compare reports, selected support geometry and accepted saves before/after on unchanged input. Measure repeated-build counts if performance is claimed; no timing improvement was established by this audit.

### 8. Medium — drive planning has a shared force law, but surrounding physical estimates still have separate owners [proven maintenance issue; approximation error remains a hypothesis]

## Architecture proposal review and bounded follow-ups

[GENERATOR_ARCHITECTURE.md](GENERATOR_ARCHITECTURE.md) is directionally consistent with Simplicity First: its occurrence list removes actual duplication, and it retains existing numerical owners. The following are design proof obligations, not reasons to implement a larger framework:

- **A port list is not yet a route feasibility algorithm.** Before replacing the four-side solve, specify the smallest connector's actual free variables, continuity conditions, closure residuals, terrain/crossing inequalities and failure result. Demonstrate it can express one feasible non-perimeter link and reject an infeasible one. Do not claim generality merely because the old side switch became a list.
- **Do not revive the rejected whole-recovery polynomial as a universal connector.** [generation.cpp:949](core/src/generation.cpp#L949) records erased authored crests and amplified endpoint jets from that approach. Reuse physical turn/FVD curvature and banking where they describe the needed path, with polynomials confined to their demonstrated join/baseline roles. The revised architecture's proposed heading/hold/source-pose variables still need a concrete feasibility demonstration.
- **Resolve transfer height/window ownership jointly.** The current route stage fits rise/window from preliminary source datums ([generation.cpp:255](core/src/generation.cpp#L255), [line 284](core/src/generation.cpp#L284)); the later common baseline owns final source translations ([line 843](core/src/generation.cpp#L843), [line 896](core/src/generation.cpp#L896)). Declaring an earlier window immutable without the same endpoint solution can overconstrain a physically feasible route. Use one agreed result; do not stack a later repair. The common solve is useful, but its present constraints are not proof that the placement problem is solved.
- **Retain a bounded solve, not every old state.** Eight rebuilds and explicit source residuals are bounds. `convergedProvisional`, retained-alternate state, attempted/final placement copies and reranking flags at [generation.cpp:1199](core/src/generation.cpp#L1199) support the present two-stage route repair; they should not automatically become requirements of the replacement. Prefer one selected physical candidate and explicit residuals, preserving rejected evidence separately.
- **Measure before optimizing the baseline/crossing implementation.** The joint baseline materializes dense constraint vectors and rebuilds active-set QR ([terrain_baseline.hpp:167](core/src/terrain_baseline.hpp#L167), [line 253](core/src/terrain_baseline.hpp#L253)); the authored crossing scan is pairwise ([generation.cpp:825](core/src/generation.cpp#L825)). Scaling cost is plausible, not measured here. If it matters on supported requests, first remove duplicate identical constraints or use existing spatial bounds; do not preemptively introduce a solver library, incremental cache or new optimization layer.
- **Small obsolete state can go with its owning change.** `RoutePlan.transferFailures` is never incremented but is checked/reported ([generation.cpp:46](core/src/generation.cpp#L46), [line 333](core/src/generation.cpp#L333)); `shape` is fixed to zero. Dummy RNG draws at [line 391](core/src/generation.cpp#L391) preserve earlier seeded correspondence. Remove obsolete route state when that route owner is replaced, but do not silently alter exact-version replay or promise seed-equivalent output after an intentional generation change.

## Deliberate non-recommendations

- Keep the actual midpoint simulator, force-duration filter/event logic, full-rate rider histories, C3/C2 canonical geometry and interval clearance certificates. Their independent tests and bounds justify the code.
- Keep terrain, vehicle/hardware and patron containment/reach envelopes distinct. Similar-looking box dimensions are not evidence that their semantics can be unified. Public summaries are not a complete current F2291 compliance basis.
- Keep load/save revalidation and atomic replacement/cancellation semantics. They protect actual caller-owned mutable state and disk outcomes, not impossible scenarios.
- Keep the UE accepted/staging/retired lifecycle, request revisions and bounded component work. Keep independent reference calculations in rendering/numerical tests. Do not reduce coverage by making tests call the implementation they are supposed to check.
- Do not refactor frozen research, historical fixtures, rejected art or evidence into the current implementation. Preserve them as evidence; remove only obsolete *active* paths after replacement contracts pass.
